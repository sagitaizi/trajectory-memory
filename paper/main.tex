\begin{abstract}
%% ~150--230 words, one paragraph, no citations, no custom macros.
%% State: problem, gap, what we do, how it is evaluated, headline result, why it matters.
% Placeholder. Event cameras report per-pixel brightness changes with microsecond latency,
% making them a natural sensor for anticipating fast, repetitive target motion. We present a
% spiking network that observes a target moving in a repeating path, builds a memory of that
% path online, predicts its position a short horizon ahead, and signals when the motion stops
% matching the learned pattern. The network is pretrained on trajectories rendered through a
% calibrated event-camera simulator and evaluated, with frozen weights, on real recordings of
% fan-driven, pendulum, hand-moved, and motor-driven motion. We report prediction error,
% lock-on time, and deviation-detection latency against classical periodic baselines. The
% contribution is a spiking formulation of trajectory anticipation as predictive inference,
% positioned as a component of a low-latency neuromorphic tracking pipeline.

\section{Introduction}
Sight is by far the dominant sense humans use to perceive the world around them \cite{Gallego2022Event}. The retina, a thin sheet of tissue in the eye, converts raw light into nerve signals that the brain then interprets as visual images. It must extract all essential features from an ever-changing reality under varying lighting conditions. Individual neurons in the retina are about a million times slower than electronic devices, operate with far less precision, and consume ten-millionth as much power, yet the retina outperforms even our most powerful computers \cite{Mahowald1991The}.

% wording of anything that says HOW our network embodies prediction waits for Phase C.

% P1 -- Anticipation, not reaction. Biological vision does not wait for the image: the
% retina already fires ahead of a moving object \cite{Berry1999Anticipation} and adapts to
% predict the scene, passing on what departs from expectation \cite{Hosoya2005Dynamic};
% the brain is widely described as a prediction machine that models what comes next and
% attends to what deviates \cite{Rao1999Predictive,Friston2010The,Clark2013Whatever,
% Keller2018Predictive}; memory, in that picture, is a model that runs ahead of the senses
% \cite{Hawkins2004On}. One clause: it does this with parts a million times slower and
% ten-millionth the power of electronics \cite{Mahowald1991The}.
%   (bib entries for these seven are NOT yet in refs.bib -- add when writing:
%    Berry, Brivanlou, Jordan, Meister, Nature 398:334-338, 1999, doi 10.1038/18678;
%    Hosoya, Baccus, Meister, Nature 436:71-77, 2005; Rao & Ballard, Nat. Neurosci.
%    2(1):79-87, 1999; Friston, Nat. Rev. Neurosci. 11:127-138, 2010; Clark, Behav. Brain
%    Sci. 36(3):181-204, 2013; Keller & Mrsic-Flogel, Neuron 100(2):424-435, 2018;
%    Hawkins & Blakeslee, On Intelligence, Times Books, 2004.)
%
% P1b -- The engineering counterpart. Event cameras report per-pixel change with
% microsecond latency \cite{Gallego2022Event} and spiking networks compute in the same
% currency, so the biological strategy is buildable in silicon -- yet the pipelines built
% on them still react: locate, then extrapolate. A target that repeats its motion is
% exactly the case where anticipation is possible.
%
% P2 -- The problem, plainly. A single target repeats a path; from the event stream alone,
% learn that path, predict the target's position a short horizon ahead, and signal when the
% motion stops matching -- hard because the target is real and freely moving, the path is
% acquired online rather than from a labelled batch, and the break signal must come from the
% same model that predicts \cite{debat2021event,pingpong2025egocentric}.
%
% P3 -- Why spiking. Events are spikes, so a spiking network can consume them without a
% framing step; the network's own dynamics carry the learned pattern and produce the
% prediction, rather than a separate regressor on top; and the result maps onto neuromorphic
% hardware -- the claim is event-native operation and dynamics-as-predictor, not better
% accuracy than a periodic Kalman filter on clean motion.
%
% P4 -- What we do. A pipeline of event front end, localiser, and trajectory memory produces a
% short-horizon prediction and a deviation score from prediction error; it is pretrained on
% trajectories rendered through a calibrated event-camera simulator \cite{hu2021v2e} and
% evaluated with frozen weights on real recordings against classical periodic baselines.
%
% P5 -- Contributions (bulleted) and a one-sentence roadmap of the paper:
%   - a spiking trajectory-memory network that learns a repetitive target path online and
%     predicts it a short horizon ahead;
%   - a deviation signal derived from prediction error that flags when motion leaves the
%     learned pattern;
%   - an evaluation protocol: simulator pretraining with a calibrated camera model,
%     frozen-weight testing on real recordings, against periodic baselines.

\section{Related Work}
% Budget ~1 column, at most 1.25. Write the gap sentence (P5) first; make every paragraph
% lead to it. Not here: attention / Itti--Koch (Discussion), external datasets (Experimental
% Setup), deep-learning trajectory surveys (one sentence at most, or cut).
%
% P1 -- Event-based trajectory prediction with SNNs. The closest systems predict where a ball
% will land from an event stream \cite{debat2021event,pingpong2025egocentric} or learn driver
% motion on neuromorphic hardware \cite{ndrivermotion2024}, but all of them share a static
% camera, one-shot ballistic motion, offline batch training, and no signal when the motion
% changes.
%
% P2 -- Sequence memory and dynamical prediction in spiking networks. Reservoirs trained with
% FORCE \cite{sussillo2009generating,nicola2017supervised}, the Legendre Memory Unit
% \cite{voelker2019lmu}, and local learning rules for recurrent SNNs
% \cite{bellec2020eprop,gilra2017predicting,kim2018learning} let a spiking network hold and
% reproduce a periodic low-dimensional signal -- the lineage of "the dynamics solve the
% prediction" -- but are demonstrated on abstract signals, never driven by a real sensor.
%
% P3 -- Novelty and deviation detection with spiking networks. Inhibitory plasticity
% \cite{schulz2021novelty} and short-term synaptic depression make familiar input quiet and
% leave novel input loud, and engineered SNN detectors handle generic time series
% \cite{vacuumspiker2025}, but novelty there means stimulus identity, not departure from a
% learned spatial motion pattern.
%
% P4 -- Classical repetitive-trajectory learning: the baselines. Rhythmic dynamic movement
% primitives \cite{ijspeert2002rhythmic,saveriano2023dmp}, a Kalman filter with a periodic
% motion model, and harmonic regression learn and reproduce a repeated path well and may beat
% a spiking network on raw accuracy for clean periodic motion; the claim here is event-native
% operation, online acquisition, and a neuromorphic deployment path, not better numbers.
%
% P5 -- The gap. No published system learns a repetitive path from a freely moving real target
% through an event camera, predicts it a short horizon ahead, and signals when the motion
% stops matching -- one or two sentences, or fold into the end of P1 if space is tight.

\section{Method}

\subsection{Problem Setup}
% Target position over time; repetition; prediction horizon; deviation definition.
% Start: p(t) = target position in normalised image coordinates. Repetitive means
% p(t+T) ~ p(t) for an unknown period T (real clips: 1.0--4.0 s; sim: 0.8--4.0 s), up to
% small smooth imperfections (amplitude beating, slow centre wander, period jitter) that
% must NOT count as deviations. Task: from events alone, emit p^(t+h) for a fixed horizon
% (h = 100 ms headline; 50 ms also reported) and a scalar deviation score s(t). A
% deviation is the motion leaving the learned path -- sudden (push, turn, shrink, speed
% change) or slow (drift). Offline: no camera control, nothing in the loop. Re-learning a
% new path after a break is out of scope (say so here, once). Source: trajmem/trajectories.py.

\subsection{Baselines}
% Periodic Kalman filter; harmonic / Fourier fit; rhythmic dynamic movement primitive.
% Start (two are implemented, trajmem/baseline.py; the DMP only if it gets built):
% (1) Kalman filter with a harmonic state per coordinate, [mean, (c_k, d_k) k = 1, 2],
% each pair rotating at k*omega per step; q = 1e-6, r = 1e-4 (normalised units); the
% prediction is the same rotation carried to t+h; surprise = normalised innovation, smoothed
% with tau = 100 ms. (2) Sliding least-squares harmonic fit (2 harmonics, last 3 periods),
% evaluated at t+h; surprise = distance of the new observation from the previous fit,
% relative to that fit's residual spread. Both estimate T from a 5 s warm-up by residual
% search and keep it. Development-set numbers at 100 ms (runs/results/development_*.csv,
